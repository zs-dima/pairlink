# pairlink wire protocol

Markers:

- **INVARIANT (tag)**: a rule that MUST hold. Each `tag` is a symbol or verbatim string in `lib/` or
  `test/`, so `grep -rn "<tag>"` round-trips between this document, the code and the tests;
  `test/contract_anchors_test.dart` enforces that.
- **DELIBERATE**: an intentional decision that may look wrong; do not change it without owner
  sign-off.
- **PEER-CONTRACT**: an expectation of the other implementation that this side cannot verify beyond
  refusing the connection.

RFC 2119 keywords (MUST / MUST NOT / SHOULD / MAY) are normative. The dartdoc is authoritative for
API shape, this file for wire behaviour.

Last verified against the code: 2026-09-04.

---

## 1. Roles and topology

**INVARIANT (OutletSession):** the outlet phone (stationary, in the socket) listens and sends power
events; the panel phone (carried around) connects and drives reconnection. The phone that displays
the QR is the one that listens, since it must be reachable at the address inside the invite.

**INVARIANT (PairIdentity):** an application declares `brand`, `serviceType` and `scheme` once and
passes them to both sessions and to `PairInvite`. `brand` is bound into the session key (§4), so two
applications never share a key space even when a user types the same four digits into both;
`serviceType` is the mDNS type the platform responder advertises; `scheme` is the QR payload's URI
scheme. None of the three is a secret.

## 2. Secrets and pairing strength

Two out-of-band paths share one wire handshake. **INVARIANT (PairStrength):** the difference is
carried to the UI, which states which kind of pairing this is rather than implying the two are
equal.

| Path | Secret | Generated by | Discovery |
|---|---|---|---|
| QR (primary) | 128 random bits (`PairSecret.kScannedBytes`) | outlet phone, displayed as `<scheme>://pair?h=&p=&k=` (`PairInvite`, scheme from `PairIdentity`) | none: the QR carries the address |
| Typed code (fallback) | 4 digits (`PairSecret.kCodeLength`), `Random.secure` | panel phone, user types it on the outlet phone | mDNS via the platform responder (`bonsoir`); a hand-rolled UDP beacon is not an option, iOS gates it behind an entitlement |
| Remembered | the scanned secret of a completed pairing, kept by the APPLICATION and never by this package | nobody — the two phones already share it | mDNS, with `id=` in the TXT record (`PairSecret.pairId`): which pairing this listener waits for, never anything about the key. Only a scanned secret has one |

**INVARIANT (PairSecret):** the secret travels out of band only, never over the network in any form.
The handshake proves possession with a MAC, so a passive listener does not learn even the four-digit
code.

## 3. Wire format

Line-delimited JSON over TCP (`FrameCodec`). Every body carries `t` (type); the envelope MAY carry
`mac`, the HMAC over the body excluding `mac` itself, independent of key order and whitespace
(`toBody` is signed, never the serialized line). Frame types: `challenge`, `hello`, `welcome`,
`reject`, `power`, `ack`, `ping`, `pong`, `bye`.

**INVARIANT (kPairlinkVersion):** the version (3) is carried in `challenge`/`hello` and checked on
receipt; a mismatch is a clean `Reject(versionMismatch)` with UI copy ("update the app"), never a
mis-parse. **DELIBERATE:** strict bumps, with no capability negotiation. Pairing is ephemeral so
nothing persisted needs migrating, a cross-version pair fails once at pairing time on a first-class
path, and negotiation would switch the current fixes off for the likeliest mixed pair: a stale spare
phone in the outlet.

## 4. Handshake (v3)

1. The outlet phone speaks first: unsigned `Challenge{v, nonce}`, a fresh 16-byte nonce per
   connection. The nonce is not a secret; sending it first makes the session key un-choosable by
   either side alone.
2. The panel phone answers `Hello{v, nonce, device?}` + `mac`, proving possession of the pairing
   secret over both nonces.
3. The outlet verifies and answers `Welcome{device?}` (signed) or `Reject{reason}`.

**INVARIANT (deriveKey):** HKDF-SHA256 (RFC 5869, extract-then-expand) over the pairing secret, with
`salt = hostNonce|guestNonce` and `info = <brand>-pairlink-v3`, `<brand>` being
`PairIdentity.brand`. So neither side can fix the key alone, a captured handshake cannot be replayed
onto another connection (the host nonce is fresh), and the secret never travels.

**INVARIANT (kHandshakeTimeout):** a peer that opens a socket and says nothing is dropped after 10 s,
so a silent stranger reads as ignored rather than as a broken application. At most
`kMaxPendingConnections` (8) unproven connections are held: a memory bound, not a security rule,
since possession is still proved per connection.

## 5. Refusals and the attempt budget

`RejectReason`: `wrongCode`, `versionMismatch`, `alreadyPaired`, `tooManyAttempts`, `malformed`.

- **INVARIANT (wrongCode):** a wrong code and a bad signature get the same answer; naming which
  guess was closer tells a stranger how to guess next.
- **INVARIANT (AttemptLimiter):** the budget (5) is spent by a failed guess, a `hello` whose MAC
  fails to verify, and by nothing else. Resets, `done` teardowns, silence and malformed frames spend
  nothing: which teardown a vanishing peer produces is the operating system's choice (Linux resets
  where Windows is silent), and counting them would hand an uninvited peer a free lockout. A spent
  budget fails closed, refusing everyone including takeover, until the user regenerates the code,
  which is also how they learn somebody was trying.
- **INVARIANT (alreadyPaired):** a live session refuses a second peer. A correct guess is neither
  budget-spent nor an eviction: exhaustive guessing can lock out, never displace. A refusal arriving
  after a successful pairing is reconnect churn, not a verdict, and never reaches the user as a
  failure; the returning panel is answered `alreadyPaired` for a few seconds while the dead
  connection times out.

## 6. Paired session: liveness, takeover, delivery

- **INVARIANT (kHeartbeatInterval):** the panel drives the heartbeat (`Ping` every 5 s), since it
  already owns reconnection. Any MAC-verified frame counts as life, not just pings.
- **INVARIANT (kIdleTimeout):** 15 s of silence on a paired connection is a verdict (three missed
  pings). A router power cut kills a peer without a FIN; with no deadline of its own the outlet
  holds its single slot until the TCP keepalive fires, roughly two hours later.
- **INVARIANT (kTakeoverAfter):** a fully valid handshake may evict the paired connection only after
  10 s of its silence: more than one heartbeat interval, so a live peer never looks that quiet, and
  less than the idle timeout, or takeover buys nothing. Cryptography cannot tell the returning panel
  from someone who read the code, since they hold the same secret; silence can.
- **INVARIANT (kMaxQueuedEvents):** undelivered events ring-buffer at 64, dropping the oldest,
  because the newest state is the product truth. **DELIBERATE:** lost/restored pairs are not
  coalesced; it would falsify the journal's transition count for no memory benefit at this cap.
- **INVARIANT (seq):** `Power.seq` is a monotonic per-session counter carrying replay rejection,
  ordering, and exactly-once delivery after reconnect (`Ack.seq` = highest stored).

## 7. Clocks

**INVARIANT (atMs):** ordering, comparison and replay checks read the monotonic stamp
(`Power.atMs`, platform `elapsedRealtime`/`systemUptime`); the wall clock (`wallMs`) rides along for
display and the journal only. A phone coming back online corrects its wall clock, often backwards,
and against a wall-clock rule that correction is indistinguishable from a replay. **DELIBERATE:**
monotonic semantics differ across platforms (Android counts through deep sleep, iOS pauses);
accepted, because stamps only compare within one session against neighbours from the same source.

## 8. PEER-CONTRACT

- The peer MUST treat the session key as connection-scoped and derive it as §4 specifies; a key
  cached across connections fails verification against the fresh host nonce.
- The peer MUST NOT retry a spent handshake on the same connection; the socket is closed after
  `Reject`.
- Moving the MAC to an AEAD, or adding encryption, MUST bump `kPairlinkVersion` (§3).
  Confidentiality of power events is not a goal, since they reveal only that mains power dropped or
  returned; the secrecy goal is the pairing secret and session integrity.

## 9. Change guardrails

Tests pinning this contract: `test/session_test.dart`, `test/heartbeat_test.dart`,
`test/session_key_test.dart`, `test/frames_test.dart`, `test/invite_test.dart`, and the adversarial
`test/skeptic/` suite, whose `hostile.dart` is an independent attacker implementation to extend in
place of the production code. `test/contract_anchors_test.dart` fails when an INVARIANT tag here
loses its anchor.

Rules:

1. Never weaken or delete a skeptic test; a new attack goes into `hostile.dart` first.
2. Any frame-shape change bumps `kPairlinkVersion` (strict, no negotiation, §3).
3. Update this document in the same change that alters wire behaviour, and refresh the
   "Last verified against" line.
